## Causal attribution boundaries

Both worker preflight phases returned0 (PPGT104.0427s, ESA20.5074s), and their
saved native certificates declared repeat/resume agreement. Certificate claims
alone are not host acceptance; the independently retrieved proof bytes are
checked separately. The all-arm barrier did allow both training processes.

The frozen PPGT source at ce3ac5a8 implements forward as a Python loop over all
validated graphs, calling the complete graph_forward independently and stacking
the outputs. Each graph also computes RRWP and SPE within graph_forward and
executes eight pair-stem plus16 backbone blocks. At physical BS128 this does
not batch the graph kernels. This establishes serial graph execution and
repeated feature work, not the exact proportion of native time in Python,
feature derivation, GPU launch, attention, backward, loader or checkpoint IO.
An operator/profile measurement would be needed to apportion those costs.
ESA's model path does batch padded edge tokens, so the two execution costs
should not be assumed equivalent from parameter counts alone.

The prior whole-shard rehash issue was repaired in the submitted loader. No
retained profiling proves that it caused this new run's slow PPGT interval.
The scientific small-model recipe must not be silently narrowed, rebatched or
converted to mixed precision to mask an execution implementation problem.
