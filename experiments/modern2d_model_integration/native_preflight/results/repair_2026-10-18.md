## Findings and smallest changes

| Finding | Evidence and repair |
|---|---|
| The entry assumed launch metadata existed at an immediate child of the input root. | The retained line42 failure and independent CPU fixtures established the unsupported-layout boundary, not the failed worker's actual layout. A shared stdlib resolver checks two exact source-identity-bound locations without recursive discovery. |

| A convenient runtime import could undermine the frozen source binding. | Preparation embeds the exact packaged resolver, not an import from the developer checkout. Launch bytes are bounded and pinned before parsing; the archive is pinned, then embedded helper bytes are compared with its regular archive member before runtime execution. |

The resolver supports `input/slug` and `input/datasets/owner/slug`, rejects
duplicate roots even if only one contains the requested marker, and rejects
links, path traversal, non-directory components and non-regular markers.
It never chooses a different identity just because that location is available.
Unknown layouts are rejected with evidence rather than searched recursively.

Reusable code lives in `src/molgap/kaggle_mounts.py`. The platform entry remains
a bounded bootstrap; the existing source package, accepted indexed loader,
Session, optimizer, sampler, checkpoint state, deadlines, GPU isolation and
qualification-only six-update admission retain their owners. No new submission
framework, training loop or scientific-contract version was introduced.
