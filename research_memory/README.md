# MolGap Research Memory Layer

RML is the deterministic, committed index over MolGap research evidence. It
does not replace experiment decisions, acceptance records, V5 evidence,
`CURRENT_STATE.md`, or authoritative remote scheduler state.

The dated [local reconciliation](operational_reconciliation_2026-10-01.md)
records closure of stale prospective ACTIVE plans. Separate arm trajectories
must not be counted as separate physical job groups.

The [2026-10-13 publication-scope review](publication_scope_2026-10-13.json)
distinguishes reviewed historical overlays from already committed experiment sources.

Canonical inputs remain beside their owning experiment:

- `trajectory.json`
- `costs/*.json`
- `roles/*.json`
- `trace_manifest.json`
- `comparison_readiness.json`
- `reference_bundle.json`
- `handoff/READY_FOR_DESKTOP.json`

Everything under `derived/` is generated by the standard-library-only compiler
and must not be edited manually.

For Spec v2 per-arm planning and terminal descriptors, use the
[shared local CLI](../docs/operations/EXPERIMENT_CLI.md). It delegates to this
RML rather than replacing it. The optional
[same-run reference binding](../docs/operations/EXPERIMENT_PROSPECTIVE_PLANNING.md)
does not authorize baseline retraining or upgrade historical trajectories.
Run from the selected checkout with its project virtualenv, not system Python.

```text
.venv\Scripts\python.exe -m molgap.research_memory validate
.venv\Scripts\python.exe -m molgap.research_memory rebuild
.venv\Scripts\python.exe -m molgap.research_memory status
.venv\Scripts\python.exe -m molgap.research_memory doctor
.venv\Scripts\python.exe -m molgap.research_memory check --frozen
.venv\Scripts\python.exe -m molgap.research_memory check --frozen --portable
.venv\Scripts\python.exe -m molgap.research_memory package-ready --trajectory <trajectory-id>
.venv\Scripts\python.exe -m molgap.research_memory backtest-screening
.venv\Scripts\python.exe -m molgap.research_memory plan --spec plan.json --output experiments/<new-question>
.venv\Scripts\python.exe -m molgap.research_memory finalize --trajectory experiments/<question> --terminal <retained-directory> --trace <trace.json>
.venv\Scripts\python.exe -m molgap.research_memory recover-trace --source <retained.csv> --spec recovery.json --output <new-trace.json>
.venv\Scripts\python.exe -m molgap.research_memory replay-pool
.venv\Scripts\python.exe -m molgap.research_memory backtest-policy --policy-id <id> --policy-version <version>
.venv\Scripts\python.exe -m molgap.research_memory terminal-pipeline --trajectory experiments/<question> --terminal <retained-directory> --trace <trace.json>
```

`check --frozen --portable` additionally checks committed evidence/runtime
closure and explicit local artifact claims; it does not fetch missing artifacts
or qualify remote-only evidence. `terminal-pipeline` accepts `--trace-source`
and `--arm` through shared trace wiring. Server planning/finalization remains
server-owned only; these entry points do not import desktop operational custody.

Planning and finalization require committed Git attributes that preserve new
hash-bound evidence bytes. `experiments/.gitattributes` and
`research_memory/policies/.gitattributes` disable text, filter, ident and encoding
conversion; extra bound paths need the same rule before publication. Existing
accepted bytes are not normalized or rewritten. `check --frozen` uses the same
metadata projection as rebuild; payload qualification remains the strict
acceptance owner's task, independent of unrelated historical weights.

RML is pointer-only. Repository pointers are root-confined; supported remote
locators remain explicit URIs. Missing historical facts remain missing, and no
command submits training, accesses protected data, changes a scientific gate,
or creates desktop/server live orchestration.

The bounded server-side retrospective V5 conversion inventory is recorded in
`v5_trajectory_conversion_audit.json`; it is coverage evidence, not live state.
The additive V5 comparison schemas are
`schemas/comparison-readiness-v1.schema.json`,
`schemas/reference-bundle-v1.schema.json`, and
`schemas/target-transform-asset-v1.schema.json`. Historical records remain
partial unless their retained artifacts establish each field directly.

The additive implementation contracts, input shapes, transaction layout and
replay metric definitions are in [LIFECYCLE.md](LIFECYCLE.md). Policy versions
live in [policies/](policies/README.md). `backtest-screening` retains its existing
grouping output; `backtest-policy` supplies evaluated policy reports. Rebuild
also writes `replay_pool.json` and `policy_backtest.json`. Historical external
traces without a retained canonical artifact and hash remain explicit exclusions.

For a scheduler-assigned ID absent from an otherwise frozen prospective
NO_TRAIN diagnostic, terminal packages may supply `postlaunch_run_binding_ref`.
The binding must hash the original trajectory plus real local submission,
scheduler and started receipts with the same job/source/archive identity.
Only completed `NO_TRAIN / context_only` diagnostics qualify; training traces,
existing frozen run overrides, action replay and causal claims are rejected.
The terminal overlay adds the ID while the original snapshot remains unchanged.
This provenance repair does not confer training replay readiness.

## Query, analysis and corrections

```text
python -m molgap.research_memory cards [--outcome OUTCOME] [--term TERM]
python -m molgap.research_memory lookup [--mechanism M] [--failure-mode F] [--family F] [--term T]
python -m molgap.research_memory gaps
python -m molgap.research_memory analyze --op {paired,ensemble-curve,residual-corr,summary,floor} --predictions PATH... | ARM=PATH... [--pair CAND=REF] --role-id ROLE --out OUT
python platforms/local/infra_budget.py
```

`cards` prints one JSON line per closed trajectory. `lookup` returns matches, families with no
measured negative result (`unfalsified`) and search terms. `gaps` lists single-trajectory families
and outcomes that differ across scale; these are review prompts, not findings. `analyze` reads saved
development predictions only: it refuses `official_validation`, `test_dev` and `test_challenge` as
`--role-id`, writes only outside `research_memory/` and `experiments/`, and marks every output
`posthoc: true` (never a gate decision). `infra_budget.py` prints each size metric against
`docs/operations/INFRA_BUDGET.json` and exits 1 when any metric is over its limit.

Per-arm closure facts (`molgap-closure-facts-v1`, passed as `--arm-facts-ref ARM=PATH` or
`facts_ref` in a closure input) hold `failure_mode` (a fixed enum), up to 8 `search_terms`, and
optional `effect_meV`/`ci_meV`, which must equal the candidate's pair in the measured `source` file.
`draft-closure` writes them with the measured numbers and null interpretation.

An erratum (`molgap-erratum-v1`, `artifact_class: narrative`, `effect: narrative_only`) lives in the
target experiment's `errata/` and excuses only a narrative `.md` decision file whose recorded and
observed SHA-256 exactly match its `recorded_sha256`/`observed_sha256` pair. It affects `validate`
only, which reports the file under `known_gaps`. Strict recheck (`accept_run.py --strict --execute`)
does not read errata, so a run blocked on such a mismatch stays `BLOCKED`; when the two disagree,
strict recheck holds for replay.
