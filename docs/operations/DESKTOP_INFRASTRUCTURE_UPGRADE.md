# Desktop infrastructure upgrade

This record owns the October 19, 2026 generic infrastructure migration. The
[quickstart](EXPERIMENT_QUICKSTART.md) owns daily use; scientific recommendations,
experiment decisions and remote jobs retain their existing owners.

Reviewed server tip: `aa16ed0a92153d948aa906813ae82f0295f2e83e`;

The migration adds a single capability catalog with derived adapters, human-input
compilation, explicit machine storage roots, content-cached source packaging,
frozen-run recovery and platform entry integration. Shared training/state/session,
model substrate and packed/fixed data move from desktop's own implementation into
namespaces with old import aliases and pickle identities preserved.

PPGT and ESA are deferred. Desktop family/addon declarations, GPTrans bond/local
support, seed policy, native training/EMA defaults, full/SCNet routes, target/data
checks and V5/RML closure remain desktop-owned. No new model, training submission,
protected-role consumption or native/scientific qualification is claimed.

## Reuse and compatibility differences

Generic IO/path/declaration helpers, V4 bundle, source packaging, run resolver,
local runtime, artifact inventory, timing/staging modules and local platform entry
reuse the server implementations directly. The Kaggle entries reuse the reviewed
server adapters. Catalog projection helpers also use the server source directly.
There is no second implementation of the same packaging or journal state machine.
The final source comparison records 19 complete files identical to their selected
server revisions and 191 top-level definitions with identical source text across
45 compared production files. Mixed files retain the compatibility differences
listed below; this comparison is a migration record, not a future test gate.
The durable-recovery blocks and allocation helper come directly from the earlier
server recovery implementation, before research-specific runtime extensions.
They extend the desktop's existing single execution loop, retaining its budget,
seed, independent-worker and standard-log behavior.

Necessary desktop differences remain at existing compatibility boundaries:

- Catalog contents and namespace implementations preserve desktop's existing
  declarations and training/data/model behavior, including legacy import aliases.
- Scientific input binds desktop's required dataset manifests and registered
  policy versions and reuses desktop's existing runner interface map;
  CLI/workflow/recovery preserve target identities and original terminal closure.
  Existing validators and RML schemas are not replaced.
- Legacy prospective declarations bind the exact source commit. Their existing
  staging retains prospective/acceptance bytes without adding a self-referencing
  commit to the source distribution. Generated V2 metadata uses the server path.
- Explicit legacy inventories retain desktop owners and exclude absent server
  modules and the desktop credential alias. Desktop's explicit serialization
  owners remain in source closure. The legacy registered source selector remains
  the desktop implementation because desktop initialization preflight still
  requires its original family modules. The new fixed tracked runtime profile
  remains the shared server implementation.

New resume launches use the shared launch validator after staging, so a checkpoint
changed after freeze blocks release. Worker arguments reuse the existing family
resume-preflight hooks. A desktop dataset-mount probe now permits its temporary
root to exist, fixing root-level manifest handling on Windows without weakening
dataset identity checks.

The quickstart is the normal entry. Existing API/history documents remain linked
lookups; no cumulative migration audit is required for ordinary configuration.
Tests load historical CLI helpers on demand. Document line-count gates are
removed; link and behavioral checks remain. The historical source inventory is
verified against its actual adoption commit
`137f4139c25dd79f6cbfa84303ecbb940b6fcba8`, rather than requiring today's evolving
implementation to match historical bytes. New releases bind their own sources.
Executed one-time relocation/catalog/constant snapshot comparisons stay in the
external migration report. Normal tests retain import, pickle, state and behavior
compatibility without freezing all future source bodies or catalog additions.

The desktop profile is external at `D:/molgap-machine-profile.json`; new data,
artifacts and scratch have separate external roots. Existing frozen payloads are
not moved or downloaded. One temporary code worktree shares the primary Python
environment and is retired after integration; it is not a permanent evidence copy.

## Lifecycle slimming from 792d688d

This revision keeps the shared trainers and frozen scientific contracts. New
planning uses one immutable knowledge/policy snapshot across arms; compact terminal
inputs reference canonical components. Legacy records remain readable and are not
rewritten. Terminal arms finalize independently before one derived rebuild, with
receipt-only index recovery. Same-job pairing and authorized versioned retries use
the existing scientific-input, acceptance and identity owners.

Default preparation output is compact; repeat inspection no longer leaves timing
files. Bound upload copies and byte-identical failed preparations have journaled
retirement. Recipe-controlled resume retention removes proven duplicates only.
Complete shared caches and unique historical chunks remain retained: concurrent
readers and unique recovery value cannot be inferred from age or file count.

Canonical curves bind actual last-update LR and checkpoint identity. Synchronous
publication reuses its new-checkpoint digest; independent recovery still hashes
visible files. Resume copies stream, and completed profiler capture removes its
hooks unless continuing spans were explicitly selected. Data loading and the
broad runtime source boundary remain unchanged pending representative measurements.

The four-arm synthetic planning fixture (201 known evidence entries) changed from
16 files / 241,152 bytes to 9 files / 40,317 bytes. These are logical fixture bytes,
not measured disk allocation or a production speedup. Source-level newly written
checkpoint digest reads fall from three (timed pass) or two (ordinary pass) to one
inside the publication transaction. CPU toy timings establish no accelerator
throughput claim. Focused test logs live outside Git under
`D:/molgap-review-reports/lean-research-lifecycle/`; unchanged passing selections
are not mandatory reruns at commit or handoff.
