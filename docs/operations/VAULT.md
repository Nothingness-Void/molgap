# Obsidian vault

The vault is a read-only view of this repository and of the run artifacts. It
lives outside Git, at `D:/molgap-artifacts/molgap-vault`. Its layout and finish
gate belong to the [vault skill](../../skills/molgap-obsidian-vault/SKILL.md).

It is not an authority, not the basis for the prior-evidence check (use
`research_memory` and [families.md](../../research_memory/derived/families.md)),
and not the basis for a submission. The repository decides; if they disagree,
rebuild the vault.

## Who uses it

- **Reader or planner:** open `00_总览看板.md`, then follow a note back to the
  decision file in the repository.
- **Closer:** nothing by hand; the closure hook refreshes it.
- **Note writer:** write only in the hand-written zones, then run the skill's
  build and validate commands.

## Zones

The skill's zone table is the only list. In short: models, ensembles, papers,
mechanisms, `rml_evidence/`, the overview, `.base` and `.canvas` files are
generated; `notes/`, `reading/` and `_templates/` are hand-written; `_data/`
holds the registries. The new `summaries/` folder is generated by
`_scripts/rml_summaries.py` (closed directions, cross-scale retention, errata,
each number with its source). Never edit a generated page.

## Updates

Closing a run calls `refresh_vault` once, after the RML rebuild. A vault failure
never fails the closure; the result carries `vault_refresh`. To rerun by hand,
run `_scripts/refresh_vault.py` with `MOLGAP_REPO_ROOT` set to the checkout.

| Variable | Effect |
|---|---|
| `MOLGAP_VAULT_ROOT` | Vault location (default above) |
| `MOLGAP_VAULT_AUTOREFRESH=0` | Skip the closure refresh |

Vault links use paths relative to the repository root, so they hold in any
checkout.
