# Formal Modern2D reference screens

This additive admission reuses the family Recipe, Session/Core, AdamW, sampler,
checkpoint transaction, Logger, source package, prospective planner and Kaggle
submission journal. It does not introduce a training loop or submitter.

## Version boundary

| Model implementation | Formal execution interface | Retained preview |

| PPGT author-derived v2 | `ppgt_small/3` | `ppgt_small/2` |

Formal interfaces use the same factories, exact configuration and existing
seed42 initial-state tensors. Their separate version means new source/recipe,
authority and ordinary native certificates, not a new model architecture.
Old CPU, preview and qualification certificates retain their original limits.

## Authorized first use

The 2026-10-18 human grant covers two independent reference screens on the
accepted V2 train100K/Common-Dev50K asset, seed42, physical BS128 per isolated
T4, FP32/TF32-off,60 passes (46860 optimizer steps). Total authorization is
9 allocated T4-hours: T4x2 for at most4.5 wall hours, including Python bootstrap,
preflight, idle devices and output retention. Unobserved pre-Python provisioning
or billing intervals remain missing, never zero or inferred from queue state.

The symmetric pilot uses existing AdamW (betas0.9/0.999, epsilon1e-8), LR1e-3,
weight decay1e-5, four-stage warmup over the first4/60 of optimizer steps, then
cosine to1e-6; gradient clip1, noEMA, unchanged zero dropout/SD configurations.
These are prospectively chosen pilot parameters, not a claim of paper-optimal
settings or a reproduction of published full-data scores. Qualification's
two-step cosine recipe is not extended or relabeled as formal training.

There is no accepted K1/GPTrans reference under this exact V2/Common-Dev
contract. The first two outputs establish independent reference observations;
they do not establish strict causal superiority, promotion or Replay. New
reference release has its own narrow acceptance-plan adapter; the existing
matched-reference gate is unchanged. 100K cannot automatically veto500K, and
neither STQS nor an uncalibrated metric-based early-stop rule controls training.

## Release and stopping

`modern2d_training_prepare.freeze_formal_screen` consumes the existing accepted
role metadata, original configurations/initial files and an independently
verified whole-CommonDev target digest. It writes declarations only. The normal
`--experiment` workflow handles packaging, original frozen identity and journaled
submission; it does not gain a general Modern2D scientific-config compiler.

Both arms must pass fresh ordinary native repeat/update/resume preflight before
either starts training. The formal context binds source/package, recipe, account,
logical run, accepted role permits and exact feature derivation. A qualification
certificate alone cannot satisfy this contract.

The allocation runtime supplies an absolute monotonic deadline. At10 minutes
before its wall ceiling, workers pause through the existing Session checkpoint
path; the allocation retains independent arm outputs and shared cost evidence.
Partial execution is `STOP_FOR_COST`/`INCONCLUSIVE`, never a completed60-pass
screen or negative architecture verdict. A checkpoint is not authorization for
another allocation. No automatic continuation, extra seed,500K/full training,
Audit, official validation or test access follows from this grant.

Completion still requires exact-version retrieval, artifact/trajectory/role/
cost inspection and factual V5/RML terminal publication. Successful submission,
orchestrator completion and scientific acceptance are separate observations.
