# Kaggle dashboard on Linux

Use a host with the reviewed MolGap checkout at /opt/molgap, Python 3.10+ and a project venv at .venv. Use the existing MolGap environment including requests and the Kaggle SDK. The collector fills the full dashboard with account quotas, kernel names, statuses, training progress and available logs. The web reader serves that snapshot at 127.0.0.1:8766. The header language switch uses the catalog at `platforms/ims/dashboard/en.json`.

1. Create the service users kaggle-dashboard and kaggle-dashboard-web and group kaggle-dashboard. Keep the Kaggle username/key JSON files in /etc/kaggle-dashboard (mode 0600, collector owner). Copy options.example to /etc/kaggle-dashboard/options. Repeat `--credentials` for each account and `--kernel owner/slug` for each kernel. To discover kernels from bound run journals instead, set `MOLGAP_ARTIFACT_ROOT` in that same options file to the absolute directory that contains `runs/`.
2. Install the adjacent units in /etc/systemd/system. Run `systemd-analyze verify /etc/systemd/system/kaggle-dashboard*.service /etc/systemd/system/kaggle-dashboard.timer`, then `systemctl daemon-reload` and `systemctl enable --now kaggle-dashboard.timer kaggle-dashboard-web.service`. The timer waits 120 seconds after each cycle. Refresh reads the saved file. A failed collection keeps the previous snapshot. The reader marks a snapshot older than five minutes stale. An upgrade from the reduced format needs one successful collection before the new view has data.
3. Use a separate Kaggle hostname and follow the [IMS Access setup, Agent credential and mobile acceptance checks](../../ims/dashboard/README.md). Install the Access policies **before** adding the hostname to the named tunnel. Put the Kaggle ingress before its final 404 rule, targeting http://127.0.0.1:8766. Leave the origin port closed to LAN/public traffic. Verify anonymous access fails, the named viewer can refresh and the restricted Agent token can fetch only /api/status.
4. To upgrade, stop the timer, collector and web service, save the old checkout revision, units and snapshot, install the reviewed new files, verify units, reload and start the timer and reader. Restore those saved versions to roll back. No collector credential is needed for the web service.
5. **Agent visual self-check (UI / copy changes):** before marking a dashboard UI or translation edit done, serve a local snapshot on `127.0.0.1:8766`, open desktop (~1280px) and mobile (~390px) views in a browser, switch 中文/EN, and visually inspect screenshots for layout, overflow, and quota/log readability.
